# RKO Radar v7 — поиск по интернету и анализ DeepSeek

Сервис поиска публичных вопросов о РКО и банковских картах. Данные и API-ключи остаются на VPS.

## Обновление установленного VPS из GitHub

```bash
curl -fsSL https://raw.githubusercontent.com/gytfel/RKO/main/scripts/update-vps.sh -o /tmp/rko-github-update.sh && sudo bash /tmp/rko-github-update.sh
```

Установщик автоматически установит `git` (если нет), загрузит репозиторий в `/opt/rko-radar-source`, сохранит базу, пароль, настройки, исходный порт, создаст резервную копию и обновит программу. Веб-сервер доступен **только локально** на VPS.

**Все следующие обновления**, после того как в GitHub будет новый код:

```bash
sudo rko-radar upgrade
```

Эта команда получает свежий установщик и выполняет `git pull --ff-only` внутри `/opt/rko-radar-source`, обновляет код и перезапускает службу. Можно увидеть текущую версию: `git -C /opt/rko-radar-source log -1 --oneline`.

Проверить после обновления:

```bash
sudo rko-radar doctor
sudo rko-radar status
```

Если установка не удалась, установщик пытается восстановить прежний код. Бэкапы базы и конфигурации остаются в `/root/rko-radar-backups/`; автоматический откат схемы базы при несовместимой будущей миграции не гарантируется.

## Доступ к веб-панели

При порте VPS `8081` запусти **на Windows в PowerShell**, а не на VPS:

```powershell
ssh -N -L 18080:127.0.0.1:8081 root@IP_ТВОЕГО_VPS
```

После входа в SSH открой на Windows `http://127.0.0.1:18080`. Не закрывай PowerShell, пока нужен доступ к панели. На сервере служба продолжает работать после закрытия SSH или выключения компьютера.

Если порт отличается, узнай его командой `sudo rko-radar port`. Пароль панели: `sudo rko-radar password` (никому не показывать).

## Возможности

- Мониторинг заданных публичных RSS/Atom-лент, ручная проверка и периодическая проверка.
- Поиск, фильтры, оценка релевантности текстов и раздел «Возможные клиенты».
- История публикаций, стадии обработки, заметки и CSV-экспорт.
- Качество источников и отправка личных уведомлений через Telegram-бота (`sudo rko-radar telegram setup`).
- Защита паролем, локальный интерфейс за SSH-туннелем, отказ от массовых рассылок.

Новости и статьи чаще всего **не являются заявками клиентов**. Результат поиска следует проверять вручную. Уведомления уходят только владельцу панели.

## Структура репозитория

- `app.py`, `collector.py`, `db.py`, `scoring.py` — веб-приложение, сбор данных, хранилище, правила поиска.
- `notifications.py`, `telegram_setup.py` — личные уведомления в Telegram.
- `templates/`, `static/` — интерфейс.
- `tests/` — тесты.
- `scripts/update-vps.sh` — обновление по GitHub для существующей установки.
- `manage.sh` — команды управления службой.
- `Dockerfile`, `docker-compose.yml`, `setup.sh`, `install.sh` — варианты установки; для уже установленного VPS используй `scripts/update-vps.sh`, а не `install.sh`.

## Безопасность

Репозиторий **публичный**: не размещайте здесь реальные `.env`, базу SQLite, пароли, токены ботов, резервные копии или сведения о клиентах. Они должны оставаться на VPS в `/etc/rko-radar.env`, `/etc/rko-radar-notify.env` и `/var/lib/rko-radar`.

Банковскую рекламу следует размещать только при соблюдении правил партнёрской программы, площадок и законодательства.


## Мобильный доступ и вход без повторной авторизации (v5)

Для телефона оптимизированы размеры элементов и загрузка данных: независимые API-запросы выполняются параллельно, а статические CSS и JavaScript могут кэшироваться браузером.

Вход: отметка **«Запомнить это устройство»** сохраняет защищённую сессию до 30 дней (срок продлевается при активности). Пароль не сохраняется на телефоне внутри приложения; используется подписанная cookie с `HttpOnly`, `SameSite=Lax` и `Secure` при настройке HTTPS. На общих устройствах снимай галочку. Кнопка «Выйти» завершает сессию в текущем браузере. При очистке cookie, входе в режиме инкогнито, смене браузера или после истечения срока пароль потребуется снова.

Чтобы убрать *дополнительный* запрос браузера на логин `radar` и пароль, сохраняя **пароль самой панели**, сначала обнови установленную программу:

```bash
sudo rko-radar upgrade
sudo rko-radar doctor
```

Затем **однократно** запусти скрипт для существующего Caddy в Docker:

```bash
curl -fsSL https://raw.githubusercontent.com/gytfel/RKO/main/scripts/remembered-mobile-access.sh -o /tmp/rko-mobile.sh
sudo bash /tmp/rko-mobile.sh
```

Скрипт не заменяет сайт TikTok и не отключает HTTPS: он убирает только блок `basicauth` у RKO Radar, делает cookie безопасной для HTTPS и перезагружает конфигурацию Caddy без перезапуска контейнеров. Перед операцией создаются резервные копии в папках конфигурации. Требуется установленный и работающий RKO Radar, а также существующий контейнер `tiktok-grev--caddy-1` с настроенным доменом `222-167-216-247.sslip.io`.

**Предупреждение по безопасности:** после удаления дополнительного барьера Caddy панель доступна по публичному адресу и защищена только собственным паролем RKO Radar. Используй длинный уникальный пароль, не передавай его другим и не используй функцию запоминания на чужих устройствах. Это компромисс ради удобства; если нужны два независимых слоя защиты, не запускай второй скрипт.

После настройки открой: `https://222-167-216-247.sslip.io`.


## Поиск клиентов по публичному интернету (Tavily)

RKO Radar дополняет RSS автоматическим поиском по **индексируемым публичным сайтам**: форумам, обсуждениям, статьям с вопросами про РКО, ИП, ООО и дебетовые карты. Это **не доступ ко всему интернету**: закрытые группы, личные сообщения, страницы за входом и неиндексируемые сайты не охватываются. Результаты поиска — кандидаты для ручной проверки, не подтверждённые заявки клиентов. Спам и автоматические сообщения авторам программа не отправляет.

Используется Tavily Search API в режиме `basic`; можно подключить бесплатный Researcher-план (на 15 ноября 2026 года: 1000 бесплатных кредитов в месяц, без карты). [Получить API-ключ](https://app.tavily.com/) · [Стоимость](https://www.tavily.com/pricing). Доступ и тарифы определяет Tavily, поэтому не обещаем постоянную бесплатность.

**Активация на уже работающем VPS:**

```bash
sudo rko-radar upgrade
sudo rko-radar doctor
sudo rko-radar web setup
```

В ходе `web setup` введи свой Tavily API-ключ (ввод скрыт). Ключ сохраняется только на VPS в `/etc/rko-radar-search.env`, доступном root, и подключается к службе systemd. **Нельзя загружать API-ключ в публичный GitHub или отправлять в чат.** После настройки открой существующую HTTPS-панель, раздел **«Источники» → «Поиск по интернету» → «Искать сейчас»**.

Дальше поиск запускается автоматически каждые 6 часов и использует до 5 запросов на проверку, максимум 24 запроса в UTC-сутки (при таком расписании около 600–620 кредитов в месяц). Ограничение остаётся и при ручном запуске. Поиск настроен на публичные результаты за последнюю неделю; ссылки и краткие сниппеты сохраняются с указанием источника «Поиск в интернете · Tavily». Дубли URL игнорируются; найденные запросы с признаками заинтересованности попадут в раздел **«Возможные клиенты»**. При включённом Telegram можно получить уведомление о новых потенциальных запросах.

Проверить подключение: `sudo rko-radar web status`. Отключить без удаления найденных публикаций: `sudo rko-radar web disable`. RSS-источники продолжают работать независимо от Tavily. Соблюдай правила обсуждений, права владельцев страниц и требования партнёрской программы Альфа-Банка.


## DeepSeek Search + AI Analyst (v7)

RKO Radar поддерживает **DeepSeek как независимый поисковик и дополнительный слой анализа** новых публикаций RSS и Tavily. Модуль применяет модель `deepseek-flash` к заголовкам и публичным описаниям, сохраняет оценку заинтересованности, объяснение и **черновик ответа для ручной проверки**. Автоматически писать авторам программа **не умеет**. Источник данных помечается в карточке; запись в раздел «Возможные клиенты» означает **предположение об интересе**, а не реальную заявку.

Сначала [создай DeepSeek API-ключ](https://platform.deepseek.com/api_keys) и проверь баланс. **DeepSeek API оплачивается отдельно**, бесплатность не гарантируется. [Официальная документация Search](https://api-docs.deepseek.com/guides/search/) · [официальная документация Chat API](https://api-docs.deepseek.com/en/).

На текущем VPS:

```bash
sudo rko-radar upgrade
sudo rko-radar doctor
sudo rko-radar deepseek setup
```

`deepseek setup` запросит ключ без отображения введённых символов, затем спросит, включать ли **платный AI-анализ**. Ответь `y`, если хочешь поиск **и** анализ, или `N`, если пока нужен только поиск. Ключ и выбор будут сохранены в `/etc/rko-radar-deepseek.env` с правами `600`. Ключ не попадает в GitHub или базу находок. Настройки systemd подключаются обновлением автоматически. После успешного ввода ключа программа перезапустится и начнёт фоновый поиск.

Открой прежнюю HTTPS-панель, раздел **«Источники» → «Поиск + анализ ИИ»**, затем нажми **«Запустить DeepSeek»**. Запуск доступен только когда ключ настроен и лимит не достигнут.

**Ограничения стоимости:** максимум 12 запросов Search и 40 запросов AI в UTC-сутки. Плановая проверка каждые 6 часов, по 3 поисковых запроса, до 6 анализов новых результатов за проверку. Дополнительные вызовы AI могут использоваться при сборе новых RSS и Tavily публикаций, но общий суточный лимит 40 остаётся. Это предел **числа запросов, не расходов в долларах**: стоимость анализа зависит от токенов и может измениться. Внешние страницы автоматически не скачиваются через Fetch API — используется только публичный сниппет/описание из результата поиска. Если нужно, можно выключить модуль: `sudo rko-radar deepseek disable`, не удаляя сохранённые находки.

DeepSeek работает только с индексируемым публичным интернетом; закрытые чаты и личные сообщения не просматриваются. AI-оценки могут ошибаться, поэтому проверяй свежесть вопроса, тарифы и правила площадки прежде чем отвечать. Указывай партнёрскую связь с Альфа-Банком, если делаешь предложение по реферальной программе.


## Поиск клиентов на дебетовые карты и реферальные приглашения (v8)

Помимо РКО, RKO Radar теперь ищет **публичные вопросы о выборе и оформлении дебетовых карт**, а также ситуации, когда автор **сам просит реферальную ссылку или приглашение**. Это не означает, что человек согласился получать личную рекламу, точно оформит карту или соответствует условиям партнёрской программы.

В панели появились отдельные списки:
- **Клиенты на карты** — запросы на дебетовые карты, где есть признаки личного интереса.
- **Ищут приглашение** — более узкая выборка с публичной просьбой дать реферальную ссылку. Это только сигнал из текста, проверяй контекст вручную.
- **Возможные клиенты** — все найденные запросы РКО и карт, как раньше.

Tavily чередует 5 поисковых запросов за проверку: **2 РКО + 2 карты + 1 приглашение**. DeepSeek чередует 3 запроса: **1 РКО + 1 карта + 1 приглашение**. Для каждого направления используются разные поисковые формулировки и `site:`-поиск по публичным страницам, включая **Храни Деньги, Банки.ру, VC.ru, Пикабу, Хабр Q&A и Ответы Mail.ru**. Это дополнительные индексируемые площадки, **не новые RSS-подписки**: наличие публикации и её актуальность зависят от поисковика. Установленные лимиты платных API-вызовов не увеличены.

Публикации с собственной партнёрской рекламой других участников, SEO-обзоры, услуги премиального обслуживания и новости не должны отмечаться как клиенты лишь за наличие банковских ключевых слов. Старые записи без AI-вердикта повторно оцениваются после обновления, сохраняя статусы, заметки и исходные ссылки.

**Обновить уже работающий VPS**:

```bash
sudo rko-radar upgrade && sudo rko-radar doctor
```

Для Tavily и DeepSeek используются **уже подключённые** API-ключи, повторно вводить их не нужно. Перейди в **«Источники»** и нажми отдельные кнопки запуска Tavily и DeepSeek, затем смотри список **«Клиенты на карты»** или **«Ищут приглашение»**.

**Правила размещения ссылок:** прежде чем давать рекомендации, проверь условия **своего конкретного оффера** в личном кабинете АльфаПартнерс. Самостоятельные рекламные материалы требуют согласования: https://alfapartners.alfabank.ru/rules . Ссылка размещается только там, где это разрешено правилами площадки и партнёрской программы; массовая рассылка не предусмотрена.


## Почему новые разделы могут быть пустыми (v9)

Публикации в разделе **«Клиенты на карты»** — только предварительно квалифицированные вопросы (`intent_label=potential`). Ноль в этом разделе **не означает**, что поисковики вернули 0 страниц. В списке **«Карты — на проверку»** отдельно показаны и прямые вопросы, и записи со статусом «возможно», которые требуют ручного просмотра; новости туда не включаются.

Для большей полноты запросы по картам и приглашениям стали короче, без обязательного одновременного совпадения двух длинных цитат. Tavily ищет по публичному индексу за последний **месяц**, DeepSeek — по `after:` за последние **30 дней**. Более широкий период даёт больше кандидатов, но дату публикации исходного сообщения всё равно надо перепроверять. Число вызовов API осталось прежним.

В разделе «Источники» после выполнения новой проверки выводится статистика **последнего запуска** каждого движка: сколько страниц вернул поиск, сколько записей добавлено в RKO Radar, сколько исключено классификатором и сколько уже существовало в базе. Это позволяет отличить 0 результатов поисковика от 0 квалифицированных заявок. Без доступного API-ключа или при исчерпанном дневном лимите цифры не изменятся.

Установка на VPS: `sudo rko-radar upgrade && sudo rko-radar doctor`. После установки обнови вкладку браузера; при необходимости используйте Ctrl+F5. Данные, настройки, ключи, отметки обработки и заметки сохраняются. Массовых рекламных рассылок программа не делает.


## v10: строгая свежесть публикаций (7 дней)

**Проблема:** даже при поиске с `time_range` поисковые индексы иногда возвращают форумные темы четырёхлетней давности или не указывают дату исходного вопроса. Дата **добавления** записи в RKO Radar не является датой её публикации.

**Решение:**
- Tavily ищет с `time_range=week`, `start_date`, `include_published_date=true` и `filter_by_published_date=true`; после получения программа самостоятельно перепроверяет `published_date`.
- DeepSeek использует `after:YYYY-MM-DD` с периодом **7 дней** и независимо проверяет его `date` (RFC3339).
- RSS-ленты учитывают только дату **`published`**, а не время загрузки, повторного индексирования или `updated`.
- Если оригинальная дата отсутствует, не читается, находится в будущем или старше 7 дней, публикация **не создаёт свежий лид**. Старые URL с годом в пути также отсекаются.
- Для ранее сохранённых публикаций создаётся нормализованное поле `published_on`: оно заполняется из имеющегося `published_at` при безопасной миграции. Ничего не удаляется: старые или недатированные записи остаются в разделе **«Все публикации»**, но исключаются из «Возможных клиентов», «Клиентов на карты», «Карт — на проверку» и «Ищут приглашение».
- Счётчики новых обращений и проверка DeepSeek учитывают семидневную границу. Система отображает дату публикации по источнику и отдельные счётчики отсеянных **старых** и **недатированных** результатов.
- При ручном добавлении обсуждения можно указать дату исходной публикации. Без неё запись сохраняется в истории, но не попадает в список свежих обращений.

Период **7 дней** фиксирован в этой версии, пересчитывается автоматически ежедневно по UTC. Изменять существующие API-ключи не нужно. Число платных вызовов не увеличено.

**Ограничение:** метаданные стороннего поисковика иногда отражают время обновления страницы, а не дату первого сообщения в многолетней форумной теме. Поэтому свежесть **конкретного сообщения** перед ответом необходимо подтвердить на оригинальной странице. Дата из индекса — сильный сигнал для фильтрации, но не абсолютная гарантия.

После обновления счётчик «Возможные клиенты» может резко уменьшиться, вплоть до 0: теперь недатированные и старые сообщения не маркируются как новые. Проверь статистику «Источники»: строки «старые» и «без даты» объясняют, почему поиск не добавил публикации.

Команды для уже установленного сервера:

```bash
sudo rko-radar upgrade && sudo rko-radar doctor
```

После перезапуска веб-панели обнови страницу (`Ctrl+F5`) и запусти Tavily и DeepSeek из раздела «Источники». Существующие пароли, API-ключи, Telegram, VPS, база, заметки и статусы обработки сохраняются.
